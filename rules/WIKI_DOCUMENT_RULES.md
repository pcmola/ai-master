# Azure DevOps Wiki 문서 관리 규칙

> 필수: Wiki 문서를 생성하거나 수정하기 전에 이 문서를 먼저 읽는다. 저장소 루트의 `AGENTS.md`도 함께 준수한다.

이 문서는 `wiki/AI-Master.wiki`의 문서·폴더 번호를 관리하는 기준이다.

## 기본 원칙

1. 기존 번호를 임의로 변경하거나 전체 문서를 일괄 재번호화하지 않는다.
2. `.order` 파일의 순서를 우선한다. 파일명 숫자순으로 자동 정렬하지 않는다.
3. 같은 상위 폴더 안에서만 번호 중복을 검사한다.
4. 번호가 같더라도 서로 다른 상위 폴더에 있으면 중복으로 보지 않는다.
5. Markdown 파일과 같은 이름의 폴더는 하나의 문서 노드로 취급한다.
6. 파일명, 폴더명, Markdown 내부 제목의 번호를 함께 변경할 때만 번호 변경으로 간주한다.
7. `99.-회의록`과 그 하위 문서는 업무 문서 채번 대상에서 제외한다.

`99.-회의록` 하위의 주간 문서와 회의 문서는 날짜 기준 내림차순으로 유지한다.
최신 날짜가 `.order`의 위쪽에 오도록 하며, 일반 업무 문서의 번호 오름차순 규칙을 적용하지 않는다.

## 최상위 프로젝트 순서

`AI-Master-프로젝트/.order`의 최상위 순서는 다음을 유지한다.

```text
02.-운영
01.-개발
```

뷰어와 문서 도구는 이 순서를 번호순으로 재정렬하지 않는다.

## 운영 영역의 고정 번호

`AI-Master-프로젝트/02.-운영`의 1depth 번호는 다음을 유지한다.

```text
01.-공통
02.-Meta
03.-Data-Portal
04.-Datalake
05.-Gen-AI-Platform
06.-Azure-ML
07.-WCSS
08.-DSP
09.-Innowork
10.-Databricks
11.-AutoRAG
90.-Knowledge
99.-회의록
```

## 하위 문서 채번

- 각 상위 문서의 하위 문서는 `01`, `02`, `03` 순으로 고유하게 부여한다.
- 번호가 이미 있는 문서는 유지한다.
- 새 문서만 해당 상위 폴더의 사용 가능한 다음 번호를 사용한다.
- 기존 문서의 번호를 앞뒤 문서에 맞추기 위해 이동시키지 않는다.
- 같은 업무명이 이미 있으면 새 문서를 만들지 않고 기존 문서를 사용한다.
- 중복 업무명을 발견하면 먼저 내용과 하위 문서 존재 여부를 확인한 뒤, 임의 삭제하지 않는다.

## `.order` 규칙

- 화면 표시 순서는 해당 폴더의 `.order` 파일에 기록된 순서를 따른다.
- `.order` 파일의 순서를 번호순으로 자동 정렬하지 않는다.
- `.order`에 없는 항목은 자동으로 앞이나 뒤에 삽입하지 말고 별도 확인한다.
- `.order` 항목을 제거하거나 바꿀 때는 해당 문서 또는 폴더가 실제로 존재하는지 확인한다.

## 변경 전 확인

- 대상 경로와 상위 폴더를 확인한다.
- 같은 이름의 `.md` 파일과 폴더가 함께 있는지 확인한다.
- 같은 상위 폴더에 동일 번호 또는 동일 업무명이 있는지 확인한다.
- `99.-회의록` 경로가 포함되면 채번·중복 정리 작업에서 제외한다.
- 확인되지 않은 문서 삭제, 전체 재번호화, 상위 Epic 번호 변경을 수행하지 않는다.

## 인코딩 규칙

1. 모든 Markdown과 `.order` 파일은 UTF-8로 저장한다.
2. Python으로 문서를 생성할 때 `encoding="utf-8"`을 명시한다.
3. 한글 문자열을 Windows 셸을 통해 전달하지 말고, Python 소스의 유니코드 이스케이프 또는 UTF-8 파일 입력을 사용한다.
4. 생성 후 문서 내용에 물음표 반복 문자열 또는 유니코드 대체문자가 포함되지 않았는지 전체 검색한다.
5. 인코딩 오류가 있는 문서만 일괄 수정하고 정상 문서는 변경하지 않는다.
6. 문서 생성·수정 후에는 서버 재시작 전에 원본 파일을 UTF-8로 다시 읽어 확인한다.

## 문서 생성 인코딩 가이드

- Python 파일 입출력은 항상 `Path.read_text(encoding="utf-8-sig")` 또는 `Path.write_text(..., encoding="utf-8")`를 사용한다.
- Windows PowerShell 명령에 한글을 직접 삽입하지 않는다. 한글은 UTF-8 Python 파일에서 읽거나 Python 문자열의 유니코드 이스케이프를 사용한다.
- 기존 문서를 수정할 때는 정상 문서의 인코딩과 줄바꿈을 유지하고, 깨진 행만 교체한다.
- 생성 직후 전체 `*.md`와 `.order`를 UTF-8로 읽어 깨짐 의심 문자열과 유니코드 대체문자 검색을 수행한다.
- 깨짐 검증이 통과하기 전에는 문서 생성 작업을 완료로 보고하지 않는다.
- 프록시 관련 문구도 한글과 영문을 동일한 UTF-8 규칙으로 기록한다.
- 주간 문서를 제외한 일반 문서는 문서별 업무 맥락이 드러나도록 내용을 다르게 작성한다.
- 동일한 프록시 문구를 여러 일반 문서에 반복 삽입하지 않는다. 문서 제목·상위 영역·업무 단계에 맞는 현황, 설치, 신청, 가이드, 점검, 장애 대응 등의 표현을 사용한다.
- 생성 후 일반 문서 간 본문 또는 업무 문구가 동일하게 반복되지 않는지 중복 검색으로 확인한다.
- 프록시 관련 문구는 `프록시` 또는 `proxy` 중 하나만 사용한다. `프록시(proxy)`처럼 두 표기를 묶어 쓰지 않는다.
